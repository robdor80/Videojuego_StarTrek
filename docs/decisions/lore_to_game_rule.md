# Lore-to-Game Rule

Status: **APPROVED GAME DESIGN**

## Principle

This repository is not being built as a Star Trek encyclopedia.

Research and lore exist to support the RPG.

Every content block must answer:

> **What does the game do with this information?**

## Required output

A block is not considered complete merely because its lore has been documented.

Where applicable, it must also produce one or more of:

- runtime/gameplay rules,
- structured authoring data,
- temporal availability rules,
- character/NPC knowledge constraints,
- authority and permission rules,
- progression requirements,
- consequences,
- location/state definitions,
- event hooks,
- validation rules,
- presentation/localization requirements.

## Two-layer model

```text
RESEARCH / LORE
      ↓
GAME MODEL
      ↓
RUNTIME CONTENT / GAMEPLAY
```

The lore layer explains **why**.

The game-model layer defines **how it works in the RPG**.

## Starfleet Academy example

Researching the Academy does not end at:
- where the campus is,
- what courses exist,
- what cadets wear.

It must also define:
- how the player enters,
- what state a cadet has,
- what locations can be visited,
- how classes/exams work,
- how specializations are selected,
- what failures mean,
- how evaluations affect the service record,
- how graduation occurs,
- how first assignment is selected,
- how the three playable eras modify those systems.

## Completion rule

**Lore-only work cannot be marked COMPLETE when the subject has gameplay relevance.**
