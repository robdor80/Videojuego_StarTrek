# Gameplay Lore Readiness

Status: **IN PROGRESS**

## Goal

Move from "we know Star Trek lore" to "the game has enough structured Star Trek knowledge to simulate, generate and validate the universe."

This work is deliberately broader than narrative reference.

Every lore domain should eventually answer four questions:

1. **What exists?**
2. **When and where can it exist?**
3. **What can it do / how does it behave?**
4. **What game systems consume this information?**

## Priority domains

### Technology and equipment

Required for:

- procedural ships;
- ship-system capability;
- away teams;
- Academy curriculum;
- repairs;
- medical/science tools;
- combat;
- computer/database queries.

Needed data includes:

- era availability;
- faction/civilization availability;
- standard vs experimental vs class-specific;
- operational constraints;
- detectable signatures;
- failure modes;
- compatible platforms;
- access/authorization where relevant.

### Medicine and science

Required for:

- sickbay;
- medical career;
- injuries and conditions;
- tricorder/diagnostic gameplay;
- xenobiology;
- environmental hazards;
- scientific analysis;
- Academy study.

Needed data includes:

- diagnostic capabilities;
- treatment categories;
- species compatibility/variation;
- scientific disciplines;
- observation/analysis limits;
- medical authority;
- uncertainty and incomplete knowledge.

### Conflicts and historical events

Required for:

- campaign starting state;

- faction relationships;
- character histories;
- procedural mission context;
- available technology;
- territorial control;
- veteran NPC backgrounds.

Needed data includes:

- regions;
- consequences;

- language;

## Game-ready lore definition

A lore area is not considered game-ready merely because descriptive prose exists.

For relevant systems it should provide, when appropriate:

- provenance;
- temporal validity;
- spatial/faction validity;
- machine-readable IDs;
- generation constraints;
- capability constraints;
- observable signatures;
- relationships to other entities;
- player-facing terminology;
- validation rules.

## Research rule

Do not fabricate canon-specific details simply to fill a schema.

When canon is silent:

- mark the field as game addition;
- use conservative design;
- preserve uncertainty;
- prefer reusable range/rule data over false precision.

## Priority order

1. Data needed by procedural-universe generation.
2. Data needed by Academy and professional gameplay.
3. Data needed by shipboard computer queries.
4. Data needed by active missions/away teams.
5. Broader catalogue depth.

## Completion philosophy

Coverage grows progressively.

The project does not need every Star Trek fact before implementation.

It does need enough structured rules that procedural generation cannot create absurd combinations merely because a catalogue is missing.
