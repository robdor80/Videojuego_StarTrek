## Método de ejecución y evidencias obligatorias

1. Una prueba unitaria de despacho para cada rechazo/revisión, más un proceso **escritor** y otro **lector** nuevos para el recorrido HM-02..08. El resultado debe derivarse de Core/F05 real. Las pruebas con dobles de fallo pueden ser complementarias, **nunca** prueba única de M0.
2. Comparar antes/después con APIs de Core y snapshots diagnósticos existentes. `f04_history_export_active` puede servir como oráculo acotado de ensayo, pero **no** debe usarse como método de recuperación. Para SAVE usar H04 y conservar originales.
3. Recoger para Linux/GCC y Windows/MSVC: SO y compilador, SHA Star Trek, pin Core, comando CMake, CTest/JUnit con conteos, jobs/URLs, fallos y SKIP explícitos. En Linux usar también Clang ASan/UBSan; además construir/cargar producto `TREK_HOST_TESTS=OFF` en ambos sistemas.
4. Pruebas reales de I/O usan carpeta **nueva** bajo `laboratorios/host/h05/` para evitar false FAIL por archivos previos; no eliminar material anterior ni forzar laboratorios al commit.
5. H05 no debe hacer benchmark de miles de años ni fingir escenario productivo: medir snapshot/H04 con campaña controlada, 1ª versión, orden completada y sucesivas versiones guardadas. Anotar tamaño total, repetición objetiva y costes; la política de deduplicación/retención sigue en H12.
6. Comparar símbolos/linkado de producto: sin `TrekF11TrialHost`, `F11_ENABLE_PROMOTIONS` ni hooks de tests; Core sigue limpio en pin, sin cambios a pruebas históricas.

## Criterios para clasificar M0

- **IMPLEMENTADO**: código nativo, cabeceras y tests en la rama de Codex, con alcance verificable.
- **PROBADO**: HM-01..HM-08 y negativas fundamentales ejecutadas contra binarios reales, CI y trazabilidad; todo SKIP residual justificado y compatible con M0.
- **CERTIFICADO**: NO en H05; certificación transversal posterior H13.
- **FUSIONADO**: solo tras PR, auditoría y fusión confirmada. No sustituir este estado por haber creado una PR Draft.

Si una limitación impide demostrar de verdad el ciclo M0 o la integridad tras LOAD, marcar el hito **BLOQUEADO** y dejar la evidencia de lo que sí pasó; **no** declararlo funcional por sustituir Core con un stub.
