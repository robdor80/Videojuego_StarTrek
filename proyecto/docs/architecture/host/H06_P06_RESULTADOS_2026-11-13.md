## Reproducción

Usar el checkout limpio de CoreRPG en el SHA indicado y una carpeta nueva en la zona ignorada para el build y sus temporales. Dirigir `TEMP`, `TMP`, `TMPDIR` y `F04_TEST_TEMP_ROOT` allí para el conjunto de regresiones. Los flags, selección y comandos exactos de las suites se conservan en el [workflow HOST](../../../../.github/workflows/host-h02-native.yml). Para repetir la denegación desde la raíz en Windows x64 (usar generador Visual Studio) o Linux (omitir `-A x64` y añadir `-DCMAKE_BUILD_TYPE=Release` al configure):

```powershell
cmake -S desarrollo/integration/host -B "$build" -A x64 "-DCORERPG_SOURCE_DIR=$core" -DTREK_HOST_TESTS=ON
cmake --build "$build" --config Release --parallel 3 --target host_abi_tests
ctest --test-dir "$build" -C Release -R '^host[.]abi[.]unsupported_academy_open$' --no-tests=error --output-on-failure
```

Para reproducir las suites Python desde un checkout con los datos versionados, dirigir `TEMP` y `TMP` al espacio temporal de la tarea. El primer intento local de la suite amplia requería ampliar el sparse checkout para incluir el manifiesto y los documentos referenciados por step 20. Se añadieron solo esas rutas de Git y se repitió completa con éxito. La paridad en vivo con la web externa queda fuera de estas ejecuciones.

```powershell
$env:PYTHONDONTWRITEBYTECODE = '1'
python -m unittest discover -s desarrollo/tools/generation -p test_generate_academy_cadet_step2.py -v
python -m unittest discover -s desarrollo/tools/validation -p 'test_f10_*.py' -v
python desarrollo/tools/generation/run_academy_life_suite.py
```
