## Matriz de interrupciones

Cada ensayo crea primero una campaña válida con servicio real, un scan, avance a
ocho días y consolidación Core. Guarda su checkpoint de diagnóstico como oráculo
de comparación del ensayo; nunca se carga ese checkpoint como campaña.

| Punto | Estado de nueva versión | Resultado comprobado |
|---|---|---|
| `before_snapshot` | Directorio creado, sin campaña preparada | La versión 1 sigue recuperable. |
| `partial_write` | Metadato escrito parcialmente, sin marcador | La versión parcial no se selecciona como confirmada. |
| `after_snapshot` | Core completo preparado, sin sobre confirmado | Se mantiene la última confirmada. |
| `after_manifest` | Sobre completo, sin publicación | Se mantiene la última confirmada. |
| `before_publish` | Preparación sincronizada, sin marcador | Se mantiene la última confirmada. |
| `after_publish` | Marcador publicado, confirmación aún pendiente | Nuevo proceso recupera una campaña completa; no mezcla versiones. |
| `before_ack` | Publicación terminada, respuesta no recibida | Nuevo proceso recupera la publicación completa. |

`persistence_process.py` ejecuta escritor, proceso interrumpido con `_Exit(73)`
y lector independientes, con timeout por proceso y por CTest. Se ejercita la
liberación por el SO de locks abandonados y se compara el Core restaurado.
Son siete interrupciones reales de proceso en puntos controlados; no simulan
un corte de alimentación física. `failures` además inyecta excepciones antes y
después de publicar: exige `PERSISTENCE_FAILED` antes y
`PUBLICATION_UNCERTAIN` después del intento no confirmable.

## Reproducción

Usar directorios nuevos indicados por el ejecutor; las salidas no forman parte
del código ni son dependencia permanente. Core debe estar limpio en el pin.

```sh
cmake -S desarrollo/integration/host -B "$build" \
  -DCORERPG_SOURCE_DIR="$core" -DTREK_HOST_TESTS=ON -DCMAKE_BUILD_TYPE=Release
cmake --build "$build" --config Release --parallel 3 --target \
  host_native_tests host_fault_tests host_persistence_tests \
  f04_tests f04_population_tests f04_history_faults \
  f05_tests f05_delegation_tests f05_initiative_tests f05_ai_tests f05_integration_audit_tests
ctest --test-dir "$build" -C Release -j 3 --no-tests=error --output-on-failure \
  -R '^(host\.|f05\.|f04\.(history_faults|thread|scope|identity|class|buffers|determinism|population_.*|process_save|process_load)$)'
```

Para MSVC añadir `-A x64`. Para Clang usar `CXX=clang++` y
`-DCMAKE_CXX_FLAGS='-fsanitize=address,undefined -fno-omit-frame-pointer'`.
El producto se construye por separado con `TREK_HOST_TESTS=OFF`.
No ejecutar dos builds sobre un mismo directorio al mismo tiempo.
