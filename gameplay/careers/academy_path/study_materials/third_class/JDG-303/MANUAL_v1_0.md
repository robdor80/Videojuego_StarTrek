# JDG-303 — Juicio operativo, informes y debriefing

**Material de estudio v1.0 — edición desarrollada**  
**Cadete de 3.ª clase · Trimestre 3**

## Finalidad

Enseñar a valorar decisiones por la información disponible en el momento y a documentarlas profesionalmente. JDG-303 convierte incertidumbre, riesgo y registro en herramientas de trabajo, evitando dos errores: presentar hipótesis como hechos y juzgar decisiones pasadas usando conocimiento que aún no existía.

La regla central es:

> **Una buena decisión no se define solo por su resultado; también por la información, autoridad, riesgo y alternativas disponibles cuando se tomó.**

---

# JDG-303-U01 — Hechos, inferencias y supuestos

## 1. Hecho

Un hecho es algo observado o registrado con procedencia.

Ejemplo:
> “El contacto aceleró a las 14:03.”

## 2. Inferencia

Una inferencia conecta hechos mediante razonamiento.

> “Puede estar intentando interceptarnos.”

Es razonable, pero no es el mismo tipo de conocimiento.

## 3. Supuesto

Un supuesto es algo que se adopta temporalmente sin evidencia suficiente.

Puede ser útil para planificar, pero debe etiquetarse.

## 4. Hipótesis

Una hipótesis es una explicación contrastable.

Debe poder ganar o perder apoyo según nueva evidencia.

## 5. Sesgo

El juicio puede distorsionarse por:
- expectativas;
- experiencia previa;
- preferencia;
- presión;
- información incompleta.

## 6. Incertidumbre

Expresar incertidumbre no es debilidad.

Permite que quien decide conozca el límite real del dato.

### Práctica

Separar hechos, inferencias, supuestos e hipótesis en un caso operativo.

### Autoevaluación

1. Diferencia hecho e inferencia.
2. ¿Qué es un supuesto?
3. ¿Qué distingue una hipótesis?
4. Nombra fuentes de sesgo.
5. ¿Por qué conviene expresar incertidumbre?

# JDG-303-U02 — Riesgo y prioridad

## 1. Riesgo contextual

El riesgo no es una cifra universal.

Depende de:
- probabilidad estimada;
- impacto;
- exposición;
- tiempo;
- capacidad de respuesta;
- incertidumbre.

## 2. Probabilidad

Puede ser:
- bien sustentada;
- aproximada;
- desconocida.

No debe inventarse precisión.

## 3. Impacto

Una consecuencia improbable puede ser prioritaria si el impacto potencial es enorme.

Y un evento muy probable puede ser de baja prioridad si su impacto es mínimo.

## 4. Urgencia

Urgencia responde:
> ¿cuánto importa actuar ahora?

No es igual a gravedad.

## 5. Reversibilidad

Una opción reversible permite corregir después.

Una decisión difícil de revertir puede exigir:
- más evidencia;
- mayor autoridad;
- más cautela.

### Práctica

Comparar tres cursos de acción según probabilidad, impacto, urgencia y reversibilidad.

### Autoevaluación

1. ¿Qué factores forman riesgo contextual?
2. ¿Por qué no inventar precisión de probabilidad?
3. Diferencia impacto y probabilidad.
4. Diferencia urgencia y gravedad.
5. ¿Por qué importa reversibilidad?

# JDG-303-U03 — Decisión bajo información incompleta

## 1. El problema real

En una operación casi nunca se dispone de información perfecta.

Esperar puede:
- mejorar conocimiento;
- consumir tiempo;
- aumentar riesgo;
- perder oportunidad.

Actuar puede:
- reducir riesgo;
- crear exposición;
- comprometer recursos.

## 2. Umbral

Un umbral de decisión es el nivel de información o urgencia suficiente para actuar.

No existe uno universal.

## 3. Consulta

Antes de decidir puede pedirse:
- nuevo scan;
- opinión técnica;
- aclaración;
- informe;
- autoridad.

## 4. Acción

Se actúa cuando:
- esperar cuesta más;
- información es suficiente para la autoridad disponible;
- existe riesgo inmediato;
- procedimiento lo exige.

## 5. Espera

Esperar puede ser una decisión profesional si:
- mejora información;
- no crea riesgo desproporcionado;
- conserva opciones.

### Práctica

Resolver un escenario con datos parciales y justificar si actuar, consultar o esperar.

### Autoevaluación

1. ¿Qué costes tiene esperar?
2. ¿Qué costes tiene actuar?
3. ¿Qué es un umbral de decisión?
4. ¿Qué consultas pueden reducir incertidumbre?
5. ¿Cuándo esperar puede ser correcto?

# JDG-303-U04 — Informe operativo

## 1. Propósito

Un informe operativo permite reconstruir:
- hechos;
- acciones;
- resultado;
- pendientes.

## 2. Hechos

Deben mantener procedencia.

## 3. Acciones

Se registra:
- qué se hizo;
- por quién;
- bajo qué orden o autoridad;
- cuándo.

## 4. Resultado

Debe distinguir:
- completado;
- parcial;
- fallido;
- cancelado;
- pendiente.

## 5. Pendientes

Una operación puede cerrar su fase sin cerrar todo el problema.

Los pendientes deben tener:
- responsable;
- prioridad;
- siguiente acción.

### Práctica

Redactar un informe de una simulación en menos de una página.

### Autoevaluación

1. ¿Qué cuatro elementos contiene informe?
2. ¿Por qué procedencia importa?
3. ¿Qué debe registrarse de una acción?
4. ¿Qué estados puede tener resultado?
5. ¿Qué debe tener un pendiente?

# JDG-303-U05 — Debrief profesional

## 1. Objetivo

El debrief busca aprender y evaluar con justicia profesional.

## 2. Hindsight bias

Es juzgar una decisión pasada como si la persona hubiera conocido el resultado futuro.

Ejemplo:
> “Debiste saber que era una emboscada.”

Si en ese momento no había evidencia suficiente, la crítica es defectuosa.

## 3. Responsabilidad

Evitar hindsight no significa eliminar responsabilidad.

Se pregunta:
- ¿qué se sabía?
- ¿qué debía saberse?
- ¿qué procedimiento existía?
- ¿qué decisión se tomó?
- ¿era defendible?

## 4. Alternativas

Se analizan otras opciones:
- coste;
- riesgo;
- información requerida;
- consecuencias posibles.

## 5. Lecciones

Una lección debe ser accionable.

Mejor:
> “Confirmar procedencia antes de elevar clasificación.”

Peor:
> “Hacerlo mejor la próxima vez.”

### Práctica

Debrief oral donde se revela después información que el equipo no conocía durante la misión.

### Autoevaluación

1. ¿Qué busca un debrief?
2. ¿Qué es hindsight bias?
3. ¿Evitar hindsight elimina responsabilidad?
4. ¿Para qué analizar alternativas?
5. ¿Qué hace útil una lección?

# JDG-303-U06 — Caso integrado

## 1. Situación

El caso combina:
- información incompleta;
- riesgo;
- autoridad;
- decisión;
- consecuencia;
- documentación.

## 2. Reconstrucción

Primero se ordena la línea temporal.

## 3. Decisión

Después se compara la decisión con:
- lo conocido;
- los límites;
- las alternativas;
- la urgencia.

## 4. Consecuencia

El resultado real importa, pero no sustituye analizar la calidad de la decisión.

Una decisión bien fundada puede tener mal resultado.

Una decisión mala puede tener suerte.

## 5. Documentación

Se revisa si:
- el log conserva hechos;
- el informe distingue inferencias;
- el debrief evita reescribir la historia.

### Práctica

Analizar una simulación completa y emitir juicio razonado.

### Autoevaluación

1. ¿Qué elementos combina el caso?
2. ¿Por qué ordenar línea temporal?
3. ¿Con qué se compara una decisión?
4. ¿Resultado bueno implica decisión buena?
5. ¿Qué se revisa en documentación?
