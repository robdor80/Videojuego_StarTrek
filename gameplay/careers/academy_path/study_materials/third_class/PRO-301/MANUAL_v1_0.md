# PRO-301 — Procedimientos operativos y trabajo interdepartamental

**Material de estudio v1.0 — edición desarrollada**  
**Cadete de 3.ª clase · Trimestre 1**

## Finalidad

Convertir acciones aisladas en trabajo coordinado, trazable y profesional. PRO-301 enseña a descomponer órdenes en tareas, estructurar informes, transferir trabajo entre departamentos, resolver prioridades en conflicto y conservar un registro factual de lo ocurrido.

> **Una operación profesional debe poder reconstruirse: qué se ordenó, quién asumió cada tarea, qué ocurrió, qué se transfirió y qué resultado quedó registrado.**

# PRO-301-U01 — Orden, tarea y responsabilidad

**Una orden expresa qué debe lograrse y bajo qué límites.** No tiene por qué dictar cada paso técnico.

Ejemplo: “Preparar ruta segura a Vulcano y reportar ETA.”

La orden puede dividirse en tareas: resolver destino, revisar restricciones, calcular opciones, seleccionar ruta, preparar ETA e informar.

Cada tarea debe tener:
- responsable;
- estado;
- resultado esperado.

El responsable confirma recepción, comprensión, capacidad para ejecutar y cualquier bloqueo.

Responsabilidad profesional significa hacer seguimiento, comunicar y escalar cuando una tarea excede la propia autoridad.

### Práctica

Descompón una orden de misión en cinco tareas y asigna responsable y condición de cierre.

### Autoevaluación

1. Diferencia orden e intención.
2. ¿Por qué se descompone una orden?
3. ¿Qué debe tener una tarea?
4. ¿Qué confirma el responsable?
5. ¿Qué significa responsabilidad profesional?

# PRO-301-U02 — Informes estructurados

**Un informe operativo debe ayudar a decidir.**

Una estructura útil separa:
- hechos;
- estado;
- riesgo;
- recomendación.

**Hecho:** “Dos matrices sensoras no están disponibles.”  
**Estado:** “Cobertura de largo alcance reducida.”  
**Riesgo:** “Menor capacidad para detectar contactos lejanos.”  
**Recomendación:** “Mantener velocidad actual hasta completar diagnóstico.”

La recomendación no equivale automáticamente a una orden. Debe formularse con claridad y dentro de la autoridad profesional del emisor.

Un informe breve prioriza novedad, impacto y decisión necesaria.

### Práctica

Emite tres informes de 30 segundos: técnico, sensor y logístico.

### Autoevaluación

1. ¿Qué cuatro capas puede tener un informe?
2. Diferencia hecho y estado.
3. ¿Qué significa riesgo en un informe?
4. ¿Quién convierte una recomendación en decisión cuando corresponde?
5. ¿Qué debe priorizar un informe breve?

# PRO-301-U03 — Handoff interdepartamental

**Un handoff transfiere una tarea, caso o paquete de información entre responsables.**

Debe incluir:
- identificador;
- contexto;
- datos relevantes;
- procedencia;
- prioridad;
- estado;
- petición concreta.

Ejemplo Sensores → Ciencia:
- contacto;
- lecturas;
- confianza;
- hora;
- análisis solicitado.

El receptor puede aceptar, pedir aclaración, devolver una necesidad de más datos o aplazar si existe una razón válida.

La transferencia no termina al enviar: debe existir confirmación de recepción y responsabilidad.

### Práctica

Transfiere un caso de Sensores a Ciencia y después de Ciencia a Mando.

### Autoevaluación

1. ¿Qué es un handoff?
2. ¿Qué datos mínimos necesita?
3. ¿Por qué importa procedencia?
4. ¿Qué respuestas puede dar el receptor?
5. ¿Cuándo se considera completa la transferencia?

# PRO-301-U04 — Prioridades en conflicto

**Dos necesidades legítimas pueden competir por recursos, tiempo o autoridad.**

Para compararlas se consideran:
- misión;
- seguridad;
- recursos;
- tiempo;
- reversibilidad;
- autoridad.

No todo conflicto es técnico. A veces ambas opciones son posibles, pero solo una encaja con la prioridad de misión.

Si el operador no tiene autoridad para decidir:
1. describe el conflicto;
2. explica el impacto;
3. presenta opciones;
4. escala.

La decisión elegida debe poder relacionarse con la información disponible y la autoridad que la tomó.

### Práctica

Resuelve tres conflictos de prioridad, uno técnico y dos de mando.

### Autoevaluación

1. ¿Qué puede causar conflicto de prioridades?
2. ¿Qué criterios se valoran?
3. ¿Por qué no todo conflicto es técnico?
4. ¿Cómo se escala profesionalmente?
5. ¿Qué hace trazable una decisión?

# PRO-301-U05 — Registro operativo

**El Operational Event Log registra hechos estructurados.**

No asigna:
- notas;
- valoraciones morales;
- relaciones;
- interpretaciones de rendimiento.

Un evento puede conservar:
- identificador;
- tipo;
- hora;
- alcance;
- actores;
- sujetos;
- procedencia;
- visibilidad;
- resultado.

Ejemplo factual:
> “Se ejecutó barrido a las 14:32.”

Una apreciación sobre la seguridad o habilidad del operador pertenece a otra capa de evaluación.

La historia es append-only: si un registro se corrige, se añade un nuevo evento que referencia al anterior.

Que un evento exista no significa que todos los NPC conozcan su contenido.

### Práctica

Crea una entrada factual de una operación y separa cualquier valoración subjetiva.

### Autoevaluación

1. ¿Qué registra el Event Log?
2. ¿Qué no debe asignar?
3. Diferencia evento y opinión.
4. ¿Cómo se corrige un evento?
5. ¿Por qué registrar no implica conocimiento universal?

# PRO-301-U06 — Ejercicio integrado

La micro-misión sigue:

> orden → tareas → coordinación → ejecución → reporte → handoff → registro

**Antes de empezar se fijan objetivo, roles, restricciones, información conocida y autoridad.**

Durante la ejecución, el equipo:
- mantiene responsables claros;
- comunica bloqueos;
- evita duplicar trabajo;
- escala cuando corresponde.

La misión termina con:
- resultado;
- pendientes;
- registro;
- relevo o debrief.

Se evalúan precisión, coordinación, comunicación, trazabilidad y disciplina.

### Práctica

Micro-misión de equipo con al menos tres departamentos y un cambio de prioridad.

### Autoevaluación

1. ¿Qué fases integra el ejercicio?
2. ¿Qué debe fijarse en briefing?
3. ¿Cómo se evita duplicar trabajo?
4. ¿Qué debe verificarse en handoff?
5. ¿Qué cierra profesionalmente la misión?
