# SIM-303 — Operaciones integradas y simulación I

**Material de estudio v1.0 — edición desarrollada**  
**Cadete de 3.ª clase · Trimestre 3**

## Finalidad

Unir conocimientos de dos años en misiones multiestación con consecuencias, registro y debrief. SIM-303 no es un examen de memoria disfrazado: obliga a trabajar con información limitada, roles, autoridad, coordinación y cambios inesperados.

La regla central es:

> **La simulación evalúa cómo trabaja el cadete, no si descubre el guion oculto.**

---

# SIM-303-U01 — Briefing y preparación

## 1. Lo visible

El briefing proporciona información que el equipo está autorizado a conocer:
- misión;
- objetivos;
- roles;
- entorno;
- restricciones;
- recursos;
- información conocida.

## 2. Lo oculto

El escenario puede contener:
- eventos;
- variables;
- riesgos;
- condiciones de evaluación

**que el cadete no conoce.**

La IA no puede revelar ese estado oculto.

## 3. Roles

Cada participante debe saber:
- función;
- autoridad;
- dependencia;
- a quién reporta;
- qué puede decidir.

## 4. Preparación

Antes de iniciar:
- revisar equipo;
- confirmar comunicaciones;
- identificar restricciones;
- resolver dudas;
- repartir tareas.

## 5. No optimizar contra el examen

Los ejes de evaluación ocultos no deben mostrarse como una checklist para “ganar”.

### Práctica

Preparar una misión simulada usando solo el briefing visible.

### Autoevaluación

1. ¿Qué información puede contener el briefing?
2. ¿Por qué existe estado oculto?
3. ¿Qué debe conocer cada rol?
4. ¿Qué se revisa antes de empezar?
5. ¿Por qué no se muestran los ejes ocultos?

# SIM-303-U02 — Operación normal

## 1. La rutina también se evalúa

Antes de una crisis puede haber:
- guardia;
- monitorización;
- tareas periódicas;
- comunicaciones;
- coordinación;
- registro.

## 2. Ritmo

**Un equipo profesional no se acelera sin necesidad ni se relaja hasta perder conciencia.**

Debe mantener:
- atención;
- prioridades;
- continuidad.

## 3. Coordinación

Las estaciones comparten información relevante sin convertir el puente en ruido.

## 4. Registro

Los eventos significativos quedan trazados.

La simulación usa el mismo principio:
> hechos en log; valoración en evaluación.

## 5. Profesión sin drama

Una fase rutinaria puede mostrar:
- fiabilidad;
- disciplina;
- comunicación;
- self-management.

### Práctica

Operar una fase normal durante un tiempo suficiente para observar consistencia.

### Autoevaluación

1. ¿Por qué se evalúa rutina?
2. ¿Qué significa ritmo profesional?
3. ¿Cómo se coordina sin saturar?
4. ¿Qué debe registrar el Event Log?
5. ¿Qué capacidades pueden observarse sin crisis?

# SIM-303-U03 — Evento inesperado

## 1. Detectar

El equipo solo puede reaccionar a:
- lo que detecta;
- lo que se le comunica;
- lo que conoce.

**No a la verdad oculta del escenario.**

## 2. Informar

El primer informe debe separar:
- hecho;
- confianza;
- impacto;
- necesidad.

## 3. Priorizar

El evento puede competir con:
- misión original;
- seguridad;
- otros incidentes;
- recursos.

## 4. Adaptar

Adaptarse significa:
- actualizar imagen operativa;
- cambiar tareas;
- pedir apoyo;
- escalar;
- modificar plan.

No significa abandonar procedimiento.

## 5. Sin guion

Puede haber varias respuestas válidas.

El motor resuelve consecuencias y la evaluación usa evidencia real.

### Práctica

Responder a un evento inesperado sin instrucciones paso a paso.

### Autoevaluación

1. ¿A qué información puede reaccionar el equipo?
2. ¿Qué separa el primer informe?
3. ¿Qué factores compiten al priorizar?
4. ¿Qué significa adaptarse?
5. ¿Por qué puede haber varias respuestas válidas?

# SIM-303-U04 — Interacción entre departamentos

## 1. Dependencias reales

Un problema integrado puede requerir:
- Sensores;
- Ciencia;
- Ingeniería;
- Navegación;
- Seguridad;
- Medicina;
- Mando.

## 2. Handoff

Cuando una parte pasa a otro departamento deben conservarse:
- datos;
- contexto;
- procedencia;
- prioridad;
- pregunta o tarea.

## 3. Conflictos

Pueden aparecer:
- recursos limitados;
- prioridades distintas;
- información contradictoria;
- competencia de autoridad.

## 4. Resolver

El equipo:
1. identifica conflicto;
2. separa hechos de preferencias;
3. plantea opciones;
4. escala si corresponde;
5. registra decisión.

## 5. Teamwork

**Trabajo en equipo no significa acuerdo constante.**

Significa coordinar desacuerdo sin romper la operación.

### Práctica

Coordinar una solución entre tres departamentos con una restricción compartida.

### Autoevaluación

1. ¿Qué crea dependencias interdepartamentales?
2. ¿Qué debe conservar un handoff?
3. Nombra conflictos posibles.
4. ¿Cómo se resuelve un conflicto?
5. ¿Por qué teamwork no exige acuerdo constante?

# SIM-303-U05 — Cierre de misión

## 1. Resultado

El cierre responde:
- qué objetivo se cumplió;
- qué quedó incompleto;
- qué cambió;
- qué riesgos permanecen.

## 2. Seguridad

Antes de declarar misión cerrada se comprueba:
- personal;
- sistemas;
- equipo;
- entorno;
- pendientes.

## 3. Retorno

La vuelta o transferencia debe mantener:
- autoridad;
- comunicación;
- continuidad.

## 4. Logs

**El registro conserva hechos y referencias.**

No se reescribe para que la misión “quede mejor”.

## 5. Entrega

Si quedan tareas o incidencias, se transfieren a:
- siguiente guardia;
- otro departamento;
- Mando;
- servicio especializado.

### Práctica

Cerrar una operación con un objetivo cumplido y dos pendientes.

### Autoevaluación

1. ¿Qué responde el cierre?
2. ¿Qué se comprueba antes de terminar?
3. ¿Qué debe mantener el retorno?
4. ¿Por qué no se reescriben logs?
5. ¿Qué se hace con pendientes?

# SIM-303-U06 — Debrief

## 1. Reconstrucción

El debrief separa:
- hechos;
- información disponible;
- decisiones;
- consecuencias;
- alternativas;
- aprendizaje.

## 2. Sin hindsight injusto

**Una decisión se evalúa con la información que el cadete tenía en ese momento.**

No con el contenido oculto que se revela después.

## 3. Alternativas

Analizar una alternativa no significa que hubiera sido necesariamente mejor.

Sirve para entender:
- costes;
- riesgos;
- señales ignoradas;
- oportunidades.

## 4. Evidencia

La evaluación debe referenciar:
- eventos;
- observación autorizada;
- informes;
- registros.

La IA puede resumir, pero no inventar evidencia.

## 5. Aprendizaje

El debrief debe terminar con:
- qué mantener;
- qué cambiar;
- qué practicar;
- qué investigar.

### Práctica

Debrief completo de la simulación.

### Autoevaluación

1. ¿Qué capas separa el debrief?
2. ¿Qué significa evitar hindsight bias?
3. ¿Para qué analizar alternativas?
4. ¿Qué debe respaldar una evaluación?
5. ¿Qué debe producir el aprendizaje final?

SIM-303 evalúa integración, criterio, coordinación, trazabilidad y adaptación.

La IA presenta escenas y diálogo; Core/World State resuelve realidad y la IA no declara por sí sola aprobado o suspenso.
